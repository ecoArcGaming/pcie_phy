  The Icarus pivot — what it changes

  The plan's toolchain (§2) is built around Vivado xsim + Verilator. Swapping to
  Icarus Verilog has real consequences worth flagging up front:

  1. SystemVerilog support is limited. Icarus (even 12.0/13.0 with -g2012)
  supports a subset of SV. It handles logic, packed arrays, always_ff/comb,
  enums, and basic interfaces, but chokes on richer constructs (advanced
  interface methods/modports in some cases, some struct/union usage, packed 
  struct edge cases). Your RTL should stay conservative — which for a PHY is
  fine. The .sv files you have will mostly work, but expect to keep things
  simple.
  2. cocotb.runner supports icarus — your run_sim.py already switched
  sim="icarus", good. That's the right call over the deprecated Makefile flow.
  3. Verilator is still worth keeping as the fast lint/regression path for
  pure-digital blocks, and it enforces stricter SV correctness. But it's
  optional; Icarus alone can carry the whole simulation deliverable.
  4. Vivado is now only needed for Phase 5's utilization/Fmax numbers and Phase 
  6 hardware. You can defer installing it entirely and still hit the "Minimum"
  Definition of Done for functionality — just note the Vivado-dependent metrics
  as pending. On Windows, Vivado is a large install; deferring it is reasonable.
